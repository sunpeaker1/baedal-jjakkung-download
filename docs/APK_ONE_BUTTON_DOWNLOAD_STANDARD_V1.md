## '진짜 다운로드' 검증 없이는 성공 선언 금지
1. 배포하려는 실제 APK 파일을 찾고 버전·패키지·기존 서명키·SHA256을 확인한다. 다른 이름의 같은 오래된 APK를 '새 버전'이라 속이지 않는다.
2. 승인된 별도 테스트 채널로 제공하되 기존 일반공개 `rider-latest`/기존 설치본을 덮어쓰거나 임의로 정식 배포하지 않는다.
3. GitHub/Vercel의 새 한글 페이지가 **실제 배포 READY 상태**이고 버튼 href가 목표 APK를 가리키는지 확인한다.
4. **실제 APK 다운로드 완료 여부**를 확인한다. 비공개 GitHub release를 직접 연결한 버튼은 모바일 비로그인 상태에서 로그인/404로 실패할 수 있어, 페이지 표시만 확인했다면 다운로드 성공으로 보고하면 안 된다.
5. 연결 도구로 모바일 다운로드까지 검증할 수 없으면 '다운로드 페이지 표시 확인 / APK 다운로드 미검증'이라고 정확히 알린다. 실패 시 기존 검증된 배포 경로의 복구 방법과 원인만 제시하며 성공을 가장하지 않는다.
6. 개인정보/비공개 앱·원본/유료 서명키나 권한 없는 APK를 사용자 승인 없이 공개 저장소에 업로드하거나 외부로 유출하지 않는다.

### 반드시 유지할 사용자 경험
- **기존 공식 도메인** `https://baedal-jjakkung-download.vercel.app`의 버전별 **한글 페이지**: 앱 아이콘 + 앱명 + 정확한 버전 + 초록색 **'APK 바로 다운로드' 버튼 딱 하나**.
- 버튼을 한 번 누르면 **비공개 저장소의 해당 APK 바이트가 직접 내려와야 함**. Google Drive 파일 보기, GitHub Releases 목록, 임시 서명 URL 화면, 복수 파일/ZIP 선택, 사설 새 사이트/서버, 채팅 sandbox 파일 첨부를 최종 기본 방식으로 쓰지 않는다.
- APK는 승인된 **기존 Vercel Blob 비공개 저장소(private)**에만 등록한다. 인증 없는 요청은 거부한다. 공개 GitHub Releases/공개 Blob/웹정적 디렉터리에 비공개 시험 APK를 올리지 않는다.
- 링크 인증(token in URL fragment)을 적용한 **비공개 버전별 다운로드 페이지**를 사용자에게 제공한다. `#token=...`이 없는 일반 주소는 화면만 볼 수 있어도 다운로드할 수 없다. **비공개 링크는 소지자에게 접근권이 생기는 형태이지 계정 본인 확인이 아님**. 유출 시 교체/폐기·재검증. 실제 token 값/저장소 자격증명/서명키는 절대로 GitHub·Google Docs·채팅 인계에 쓰지 않는다.
- 새 버전마다 APK 원본 확보 → versionName/versionCode/패키지/기존 인증서 서명/해시 검증 → 비공개 파일 등록 → 서버의 전체 SHA-256 검사 → 전용 한글 버튼 연결 → 서버 실 다운로드와 해시 재확인 → 휴대전화 다운로드·설치/현장 작동 각각 분리 판정. **V156 성공을 다른 버전의 자동 성공으로 확대 금지.**
- 가능한 것은 AI가 직접 수행. 권한상 사용자 휴대전화 파일 선택이 꼭 필요할 때만 **한 단계** 안내. 기존 페이지는 그 전에 임의 덮어쓰기 금지. 사용자 승인·보호 게이트 및 APK/배포 범위 준수.
- 기본 결과 메시지: '공식 비공개 다운로드 페이지: [검증된 링크 하나]' + 필요 시 설치 주의 한 줄. 토큰 없는 일반 URL만 내놓고 다운로드 가능하다고 하지 않는다.
