# 모든 AI·Codex·Work·총괄비서 공통 — APK 단일 버튼 다운로드 고정 규칙 V1.0
확정일: 2026-10-27 | 승인: 사용자 직접 명시

## 반드시 이 형태로 제공
- 기존 공식 웹사이트 도메인 안에서 **한글 단일 버전 다운로드 페이지**를 제공. 사진 기준 예시 `rider-v148-test.html`: 앱 아이콘 + 한글 이름 + 현재 버전 + **'APK 바로 다운로드' 큰 버튼 1개**.
- APK 설치 파일은 **정확히 한 개만** 안내한다. 영문 GitHub Releases 화면/ZIP/여러 파일 링크/복수 선택 버튼이 최종 페이지가 되지 않게 한다.
- 이미 검증된 원래 웹페이지 디자인을 참고하고 원래 배포 방식을 사용한다. 새 배포·서버·다운로드 흐름을 임의 재설계하지 않는다.
- 한국어로 **짧게 링크 하나만** 주고, 필요할 때만 주의사항 한 문장 추가한다.

## '진짜 다운로드' 검증 없이는 성공 선언 금지
1. 배포하려는 실제 APK 파일을 찾고 버전·패키지·기존 서명키·SHA256을 확인한다. 다른 이름의 같은 오래된 APK를 '새 버전'이라 속이지 않는다.
2. 승인된 별도 테스트 채널로 제공하되 기존 일반공개 `rider-latest`/기존 설치본을 덮어쓰거나 임의로 정식 배포하지 않는다.
3. GitHub/Vercel의 새 한글 페이지가 **실제 배포 READY 상태**이고 버튼 href가 목표 APK를 가리키는지 확인한다.
4. **실제 APK 다운로드 완료 여부**를 확인한다. 비공개 GitHub release를 직접 연결한 버튼은 모바일 비로그인 상태에서 로그인/404로 실패할 수 있어, 페이지 표시만 확인했다면 다운로드 성공으로 보고하면 안 된다.
5. 연결 도구로 모바일 다운로드까지 검증할 수 없으면 '다운로드 페이지 표시 확인 / APK 다운로드 미검증'이라고 정확히 알린다. 실패 시 기존 검증된 배포 경로의 복구 방법과 원인만 제시하며 성공을 가장하지 않는다.
6. 개인정보/비공개 앱·원본/유료 서명키나 권한 없는 APK를 사용자 승인 없이 공개 저장소에 업로드하거나 외부로 유출하지 않는다.

## 실제 예시와 현 상태
- 단일 버튼 페이지: https://baedal-jjakkung-download.vercel.app/rider-v148-test.html
- V148 비공개 시험 APK는 `sunpeaker1/rider-jjakkung-app` 비공개 GitHub release의 asset을 연결한 구조. 사용자 스크린샷으로 **페이지 한글 UI 표시 성공**은 확인했지만 **버튼 클릭 후 APK 다운로드 성공은 미검증**.
- 과거 형식 참고: `rider-v145-test.html`, 이전 `download-page-v1.57.78-backup.html`.
- 사용자에게 'GitHub Release 페이지로 가서 Assets를 누르세요' 같은 여러 단계 안내를 기본 제공하지 않는다.
- 후속 버전은 각 버전마다 위 표준을 적용. 이 원칙을 다른 앱 APK에도 사용하되 릴리스 승인·보호 규칙을 항상 우선한다.
